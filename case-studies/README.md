# xingtu-sdd · 实践案例库（Case Studies）

> **定位**：xingtu-sdd 的「可验证证据」层——方法论（references/）+ 引擎（scripts/）+ 真实案例（本目录），三者闭环构成个人 SDD 知识技能库。
> **原则**：每个案例都来自真实跑通的工程实践，脱敏后沉淀；每个案例尾部挂「踩坑 → 规则反哺」，与引擎方法论双向指链。

## 收录标准

1. **真实跑通**：案例来自实际落地、有验收凭证的 Spec，不是教学虚构。
2. **可迁移价值**：提炼出的方法/规则对同类问题可复用（不只是记录某次操作）。
3. **去业务绑定**：脱敏后不暴露内部项目代号、金额、个人/雇主信息、本地路径。
4. **反哺闭环**：案例必须有「踩坑 → 规则」映射，反哺引擎 references。

## 脱敏规则（不可协商）

| 项 | 处理 |
|---|---|
| 内部项目代号 | →「内部项目」 |
| 金额/账单 | → 量级表述（"量级"，不公开精确值） |
| 本地绝对路径 | → 通用化（`tools/...` 等相对形态） |
| 真名/邮箱/手机 | → XingTu（对外统一口径） |
| 微信解密 / 数据库密钥类 | **一律不收**（红线，见下） |

## 红线（绝不收录）

本地 `specs/` 中微信解密相关 5 项（解密成果总结、密钥提取全局方案、密钥 JSON、contact.db 解密、微信数据资产工程化规划）**任何情况下不进公开仓**——本地保留，案例库直接排除。
