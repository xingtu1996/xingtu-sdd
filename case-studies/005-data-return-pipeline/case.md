# Case 005 · 公众号数据回流管道

> **一句话**：把「发布 → 阅读数据 → 台账 → 选题决策」闭环里的人工环节（截图 → 手工回填）自动化——数据每日回流、只读不写、回填必须过人确认。
> **档位**：standard（数据管道档）+ validator 门禁 ｜ **状态**：✅ v1 已跑通 ｜ **原 spec**：`specs/20260914-公众号数据回流管道/`

## 一、背景问题（为什么做）

- 「发布 → 阅读数据 → 台账 → 明日选题」闭环中，数据靠人工截图 → 会话手工回填，滞后且易漏。
- 目标：数据日回流，支撑数据诊断与选题决策；**回填必须过「报告 → 人确认 → 写入」**，防数字幻觉。

## 二、Spec 结构（怎么组织）

单文件 `00_README.md`：目标与非目标（红线）→ 双通道设计 → 数据流 → 剔除规则 → 文件清单 → 验收标准 → 开放项。

## 三、关键设计（怎么实现）

- **非目标红线**：不做 API 发布（个人号群发已回收，群发永远人点）；不爬他人数据（只读自己后台）；不全自动直写台账（回填过「报告 → 确认 → 写入」）。
- **双通道设计（通道对比表）**：
  - A. 浏览器只读接管：抓「发表记录页」全量（标题/链接/时间/阅读/分享/赞/在看/评论/赞赏）——**主通道，已跑通**，风险极低（真实登录态 + 日 1 次 + 只读）。
  - B. 官方数据 API：**实测定案死刑**——个人未认证账号 7 个数据接口一律 unauthorized，探针脚本留档、日后认证可复测（**探针留档 = 决策可复现**）。
- **数据流**：发表记录页（只读）→ 每日快照 JSON（含剔除标记）→ 与上一快照 diff + 与台账匹配 → 回填报告（旧值→新值 + 来源 + 时间戳）→ 人确认 → 写入台账 → 数据诊断。
- **剔除规则**：「仅自己可见」测试发布自动剔除（页面状态字段）+ 人工名单兜底。
- **快照纪律**：每日快照 append-only 不覆盖历史。

## 四、验收标准（怎么算完成）

1. `--pull` 一次跑通：记录 ≥N 条落 JSON，测试发布被剔除标记 ✅
2. `--report` 能指出台账哪些行数据列落后于快照（已知值应被正确匹配）✅
3. 全程只读：不产生任何写入后台的操作 ✅
4. 回填纪律由快照 diff 自动提醒（数据变化 ≥ 阈值时报告标注）✅

## 五、踩坑 → 规则反哺（复利点）

| 踩坑 | 反哺规则 |
|---|---|
| 官方 API 看着能用，实测个人号全被拒 | **通道 B 先探针实测定案再投入**；探针与结论留档，认证后可复测 |
| 自动回填数字可能幻觉 | 回填必须过「报告 → 人确认 → 写入」；数据列落后由 diff 自动提醒 |
| 测试发布混进数据 | 剔除规则两层：页面状态字段自动判 + 人工名单兜底 |
| 快照被覆盖就丢历史 | 快照 **append-only**，不覆盖历史（diff 需要历史基线） |
