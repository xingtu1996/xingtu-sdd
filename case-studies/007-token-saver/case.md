# Case 007 · 省 Token 实战包装：框架 ≠ 可复用资产，要补「包装层」

> **一句话**：把散在 6 个工具的省 Token 框架做「包装层」补强——以 `prompt 包装 + skill 聚合 + config 配置` 三层形态产出可复用资产，让 95% 用户从「贴 prompt」跨到「用 skill」。
> **档位**：standard（内容/资产型 spec）｜ **状态**：✅ Phase 2/4 完成（skill 落地）｜ **原 spec**：`specs/20260906-省Token实战包装与Skill聚合/`

## 一、背景问题（为什么做）

- **框架散落 = 门槛高**：六层 Token 框架散在 CBM / rtk / Headroom / Caveman / Concise / Ponytail 6 个工具，普通用户复用要查 6 仓库 + 6 文档 + 6 命令。
- **本地配置技巧没人系统讲**：`.claude/CLAUDE.md` 写法、`settings.json` 配置、`outputStyle: Concise` 本质、prompt caching 触发、Sub-Agent 编排——市面没有体系课。
- **时机敏感**：新模型发布时特别贵，谁有省 Token 体感谁第二天还愿意付费——内容时效性强，要跟模型发布节奏。
- 核心判断：**知识框架（素材卡）≠ 可复用资产**，框架要配套「包装层」才能被普通用户用起来。

## 二、Spec 结构（怎么组织）

```
00_README.md          # 一句话定位 + 适用范围 + SSoT 锚点 + 状态块（yaml）
01 设计（包装层三层形态）
02 落地（skill 开发 + 配置盘点 + 成稿排期）
```

（素材卡 v2 扩展型 spec——在既有框架资产上追加「包装层」设计，不替代原框架。）

## 三、关键设计（怎么实现）

- **三层包装形态**：
  1. **prompt 包装**——可直接粘贴的省 Token 提示词模板（贴 prompt 是 95% 用户的起点）
  2. **skill 聚合**——一条命令/一个入口聚合六层工具能力（用户从「会查 6 个仓库」降到「会装一个 skill」）
  3. **config 配置**——默认最优、开箱即用的配置（用户零配置获得体感）
- **本地即样本**：本地 harness 本身就是「省 Token 工作空间」的实战案例（AGENTS.md / SOUL.md / RULES.md / skill 软链 / 模型路由），写内容有真实颗粒。
- **排期锁位**：月历占位（B09 配置 / DeepSeek 缓存机制已锁），后续成稿待选期——与「省 Token 合集 2→4 篇达标」战略挂钩。

## 四、验收结果（怎么算完成）

- ✅ Phase 2/4 完成：`xingtu-token-saver` skill 建成 + 用户级安装（D1=A 建 / D2=A 用户级）。
- ✅ 配置盘点完成（本地 harness 三层形态落地）。
- ⬜ Phase 3 成稿待选期（3 篇后备选题已登记选题池）。

## 五、踩坑 → 规则反哺（复利点）

| 踩坑 | 反哺规则 |
|---|---|
| 框架散在 6 工具，用户复用门槛高到放弃 | 知识资产要配套「包装层」（prompt + skill + config），框架才等于可复用资产 |
| 省 Token 内容跟着模型发布节奏走，错过窗口就过时 | 内容型 spec 排期要锁「月历占位」，跟热点窗口绑定 |
| 只有框架没有工具入口，读者「学到了但用不上」 | 每个框架资产交付时自带「可执行入口」（skill/命令/配置） |
