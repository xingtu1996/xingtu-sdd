# 可复用片段库（Copy Points）

> 与 case-studies 互补：case.md 记「怎么做的」，本库存「能直接抄的话」。
> 来源：行途 SDD 实战沉淀，脱敏后入库。新 spec 开工前 `sdd recall <关键词>` 先搜这里，避免重造金句/话术。
> 维护：每完成一个 spec，把该 spec 里沉淀的可复用表达补到对应分类下，带出处 case 编号。

## 一、对抗失控 / 模型控制类（SDD 内核话术）

- 「完成判定查凭证，不问模型」——模型把没做的事说成做了是高频幻觉。
- 「验收认磁盘不认自述」——子 agent 说做完了不算，`ls`/`grep`/实跑工具才算。
- 「交叉验证用脚本，不用 LLM 法官」——既省一轮 token，又免法官自己引入新幻觉。
- 「定位用原文片段，不用行号」——行号会漂移，grep 片段才稳。
- 「待拍板必须带默认值，不占决策人带宽」——禁开放式问题。

## 二、流程方法论类

- 「No Spec, No Code / Spec is Truth / Reverse Sync」三铁律（见 laws.md）。
- 「深度裁减」：单文件 Bug 走轻量 2 文件，架构改造才上重量全量——**不为了仪式感跑全程**。
- 「有引擎用引擎，不手搓目录」。

## 三、红队 / 审查类

- 五类靶：引用证伪 / 单一信号绑架 / 平行系统 / 口径污染 / 副本腐烂。
- 「Filter 只减不增」——拦截 30-50% 低质量发现，减轻人审负担。
- 「红队只攻击只做减法，不处置」——成立与否归主会话。

## 四、跨工具/跨会话续传类

- 「收尾即留痕：会话随时被切走，每个阶段落盘，下个会话靠文件接续不靠记忆」。
- 「recap 再动手：三五行讲清要解决什么/已做到哪/挂着什么待拍板」。
