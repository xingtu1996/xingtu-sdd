# Case 008 · 运营日报升级：从「明天发哪篇」到「全矩阵调度台 + 真正闭环」

> **一句话**：把日报从「公众号明天发哪篇」升级为**全矩阵晨间调度台**并补成真正闭环——输入（素材库/元宝卡/claude 经验/舆情）→ 加工（agent 四块决策）→ 输出必归档（调度快照+发布日志+分发凭证+变现推进）→ 结果必回流（数据反哺素材重算/去腐/选题）。专治「有输入没输出、输出没归档」。
> **档位**：standard（01~05 + execution-log + 对抗审查）｜ **状态**：✅ Phase0-2 落地并独立复核｜ **原 spec**：`specs/202609161130-qwenwork-运营日报升级_全矩阵调度与变现闭环/`

## 一、背景问题（为什么做）

- **决策引擎已存在**：素材库 `materials_library` 已有 `publish_priority / urgency / platforms` 打分、`publish_brief` 已有舆情→库存匹配 + 分发窗——**缺的不是打分，是编排**（没人串成每日调度）。
- **执行闭环从未真跑**：「凭证 = 0」是被品牌化/认证污染的**脏口径**，分发了但没有合规凭证计入闭环。
- **变现与现实脱节**：30 粉期三层产品（自查卡/小册/咨询）未开卖、私域有合规红线——日报要承接变现推进，但不能越红线。

## 三、关键设计（怎么实现）

- **三轨 + 变现编排**：轨A 首发 / 轨B 再铺（+24/48h 时序、一天≤2 平台）/ 轨C 去腐 + 自动成包 / 轨D 变现进日报。
- **凭证唯一化**：分发凭证命名 `分发凭证_<平台>_<日期>`，**排除脏前缀**（品牌化/认证/隐私类不计）——闭环率 = 合规凭证数 ÷ 建议数。
- **打分去时效化**：时效不得双重放大，防止锁死去腐榜（M030 长尾满分卡排不过 M476 时效卡是反例证据）。
- **机读 SSoT 唯一**：同名旧雷 `materials_index.json` 改名脱钩，机器只认 `materials_library.json`。
- **决策不脚本化**（对抗审查产物）：被否决的 `morning_dispatch.py` 决策系统（违背「决策是 agent 综合判断」）→ 改为 `dispatch_feed.py` **只喂数不决策**。
- **红线**：全程只读、群发永远人工；私域禁个人微信号/二维码，只企业微信/视频号私信。

## 四、验收结果（怎么算完成）

- ✅ Phase0-2 落地并独立复核：V3 producer / 轨C 自动成包 / 轨D 变现公式 SSoT 全绿；AC-3/8/9/10 收口。
- ✅ 决策四块（①主推+备选 ②怎么发 ③异常/杠杆点 ④待拍板≤2 题）写入日报文件顶部，六块降附录。
- ⚠️ 运行期闭环率 0/8 = **人工群发 + 回填凭证的执行缺口**，非开发遗留——待跑一轮非零激活。

## 五、踩坑 → 规则反哺（复利点）

| 踩坑 | 反哺规则 |
|---|---|
| 「凭证 = 0」是被品牌化/认证污染的脏口径，误判为没分发 | 凭证**唯一命名 + 排除规则**，闭环率只认合规凭证 |
| 同名 `materials_index.json` 旧雷与 SSoT 并存 | 机读 SSoT **唯一化**，旧文件改名脱钩防双写漂移 |
| 试图把决策脚本化（morning_dispatch.py 被否决） | 编排层只**喂数不决策**，决策是 agent 综合判断（不过度工程） |
| 分发建议发了但凭证不回流，闭环率永远 0 | 输出必归档、凭证必回填，闭环率 = 合规凭证 ÷ 建议数（每日重算） |
