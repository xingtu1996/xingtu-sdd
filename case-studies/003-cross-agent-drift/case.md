# Case 003 · 跨 Agent 口径漂移根治

> **一句话**：同一个事实在工作区里有 N 处副本，改一处忘 N-1 处，且每个 Agent 只读自己被注入的那份 → 用「规则 + 注册表 + 守卫」三件套，让漂移从「靠人记住」变成「跑一下就红」。
> **档位**：heavy（跨系统架构级）+ 并行 ｜ **状态**：✅ P1+P2+P3 已落地 ｜ **原 spec**：`specs/20260915-跨Agent口径漂移根治/`

## 一、背景问题（为什么做）

- 多 Agent 协作下，同一事实（工具清单 / Skill 实体数 / 编号号段 / 发布节奏）在工作区里有 3-5 处副本，各 Agent 只读自己被注入的一份。
- **实测严重度**（脚本扫盘 + 正则对账）：
  - 一个配置加值后，需同步的说明面有 5 处；
  - Skill 实体与手写索引表不一致（标称数滞后）；
  - 「开工必读」的坏例索引自己烂了：索引表停在旧编号，详情已有新条目，入口比内容旧——**防线自带盲点**；
  - 编号撞车：手写派生选题号与选题池既有号撞车，按号写稿会拿错题（后果最重的一种漂移）。

## 二、Spec 结构（怎么组织）

骨架式单文件 `00_README.md`：问题（含实测数据）→ 目标与非目标 → 方案三件套（可分期）→ 待拍板 → 实际落地结果（Reverse Sync 复盘）→ 遗留。

## 三、关键设计（怎么实现）

- **P1 规则**：规则册新增一条「枚举类事实禁止内联复述，必须写『取值以 X 为准』」，含反例正例（防再犯的规范层）。
- **P2 注册表**：机器可读清单收口一处（工具池 / Skill 实体清单 / 发布节奏引用位 / 编号取号口径），消费脚本从注册表读值，**脚本与文档同源**。
- **P3 守卫**：单一命令扫全部声明面，漂移即非零退出；接入改动闸门与定时任务；含选题编号唯一性 + 「文档里手写编号」告警。
- **非目标**（明确不做的边界）：不做跨 Agent 记忆同步总线（各工具记忆独立，接续只认变更日志 + 会话交接包）；不做文档自动重写（只报错，不擅自改人写的正文）。
- **人造漂移夹具验证**：故意制造一次漂移（改号 / 重复编号），守卫必须变红——**抓不到 = 守卫无效**。

## 四、验收结果（怎么算完成）

- ✅ P1 规则入册（rule_add 四联动）；✅ P2 注册表落地且消费脚本切换；✅ P3 守卫四面检查 + 夹具全抓到 + 真实声明面 0 线索。
- ✅ 顺带清掉的真缺陷：规则计数双标、选题池内部重号（后入池者让号）、坏例索引重号收口（保引用面最广者原号、另一条让新号）、Skill 台账重生与手抄计数收口。
- ⬜ 遗留（需人拍板，不擅自动）：是否并入聚合门禁、个别 Skill 内嵌规则正文（跨工具只读不写）、历史豁免到期续期。

## 五、踩坑 → 规则反哺（复利点）

| 踩坑 | 反哺规则 |
|---|---|
| 事实 N 处副本，改一处忘 N-1 处 | 枚举类事实禁止内联复述，**「取值以 X 为准」**；注册表收口 |
| 编号手写撞车，按号写稿拿错题 | 编号取号走注册表 + 守卫扫「文档里手写编号」告警 |
| 入口文档比内容旧（防线自带盲点） | 守卫对「入口引用位」做一致性检查，漂移即红 |
| 修完没人验证守卫是否有效 | **人造漂移夹具**：故意改一次，守卫必须抓到，否则返工 |
