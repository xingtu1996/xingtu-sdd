# Case 009 · 回收站清空前的资产保全审计

> **一句话**：清理回收站空文件夹后，用户担心「万一清空把数据资产干掉」——把这份不安换成 **五组可复跑的核查**：证明删除零损失，并**查出一个真缺口：6 张 GOLDEN 级素材卡生成了却从未入主库**（断的是工序，不是文件）。
> **档位**：light（调研档：analysis + validator）｜ **状态**：✅ 全部完成（6 卡入库 / 16 组快照迁回 / 回收站 1.9 GB → 0 B）｜ **原 spec**：本地 `specs/` 下「回收站资产保全审计」

## 一、背景问题（为什么做）

- 会话开头做的动作极小：清理回收站里的**空文件夹**（工具 `rmdir`，只能删空目录）。
- 但用户立刻提出了真正的关切：「*担心这个东西清空，会把我们宝贵的数据资产给干掉啊*」。
- **关键洞察**：担心的不是**已发生**的删除（空目录 = 0 文件，定义上无风险），
  而是**下一步**的动作——**清空回收站**。审计要覆盖的是后者。
- 缺口：工作区有「改前打快照」的纪律，却**没有「清理前置检查」流程** ——
  每次清理都靠人临场判断，于是「感觉不安」但说不出哪里不安。

## 二、核查方法（五组，互相独立，都能重跑）

| 组 | 问什么 | 怎么做 |
|:--:|------|------|
| **① 反向核查** | 我删掉的那些目录，原本装的东西现在在哪？ | 拿被删目录名，去**真源库**找同名活体目录 |
| **② 目录核查** | 回收站里的每个目录，别处有没有？ | 逐个比对「技能池 / 代码仓」等已知归属地 |
| **③ 文件核查** | 回收站里的每个文件，别处有没有？ | 逐个在全工作区树里做同名匹配；找不到 = **全机唯一份** |
| **④ 登记层核查** | 这东西当初为什么产出、谁产出的？ | 查工作区时间轴台账（含工具归属列） |
| **⑤ 内容层核查** | 处理完了没有？ | 打开看：已迁移？已并入？还是裸放未处理？ |

> 五组是递进关系：① 只需证明本次动作安全；②③ 把范围扩到「整个回收站」，为**下一步**的清空动作备证；
> ④⑤ 回答「**还能不能救、值不值得救**」。**审计的对象永远比动作大一圈。**
> ④ 能筛掉大部分，⑤ 只对 ④ 筛剩的少数做（省下逐个开箱的成本）。

## 三、关键设计（怎么实现）

- **把「删除」与「清空」分开对待**。已发生的删除用 ① 自查即可；
  「清空」是未来动作，必须用 ②③ 提前备证。混为一谈会让审计要么过度、要么不足。
- **用能自证的工具**：删空目录用 `rmdir`（非空自动失败），
  天然满足「无法误删」——**把安全性编码进工具选择**，而不是靠事后检查。
- **对唯一份文件做四分类**，而非一刀切：
  | 类别 | 判据 | 处置 |
  |---|---|---|
  | 有同名副本 | 全树命中 | 可弃 |
  | 备份快照（`*.tar.gz` + `.meta`） | **按定义就无副本** | 单独一档，标注为「历史回滚点」 |
  | 一次性杂物（安装包 / 剪贴板截图 / 日志） | 命名与时间分布可判 | 可弃 |
  | 其余 | 无副本 + 有引用线索 | **待人工拍板** |
- **识别「真源迁移的尾气」**：目录在旧位置只剩空壳、而真源库里有同名活体目录
  ⇒ 这不是 bug，是迁移完成后的正常残留。判据是**活体库里的同名目录存在且非空**。
- **关键反直觉发现**：`git status` 显示真源库有大量**未提交**改动
  ⇒ **「已进真源库」≠「已进版本历史」**。备份层不等于存档层。
- **★ 最有价值的一步：用「登记层」判定，而不是打开文件**。
  工作区台账（时间轴 CHANGELOG）每条含 `时间 | 类型 | 路径 | 为什么 | 工具归属`，
  工具列即**跨 agent 归属登记**。于是判定规则现成：
  - 台账**命中** ⇒ 是登记过的产出（有主、有 why），不必打开看内容；
  - 台账**0 命中** ⇒ 从未登记为产出 ⇒ 过程残留 / 外部输入物。
  这一条把「逐个人工开箱」换成「查一张表」，且与工作区既有规则
  「**未登记 = 不存在的资产**」严格同源 —— **登记层 = 判定层**。
  台账的路径列还会随迁移自动变化，因此**路径列本身就是迁移留痕**
  （同一条目从旧路径指向真源库路径，即「旧壳 vs 活体」的铁证）。

## 四、验收结果（怎么算完成）

- ✅ 6 条断言全部实跑通过：删除目录数 21、复查剩余空目录 0、活体归属 15/17、无独有目录 3 项已逐个说明。
- ✅ 唯一份文件量化到 93 个，并完成四分类（32 快照 / 46 截图 / 8 安装包 / 7 待判）。
- ✅ **内容层抓到真缺口**：一个增量文件含 6 张 GOLDEN 级素材卡，逐张比对主库确认 **6/6 从未并入**
  —— 文件自述「待确认后合并入主库」，在回收站躺了一个多月。**断的是工序，不是文件。**
- ✅ 核心处置已执行：6 张卡并入主库（**2567 → 2573**）；16 组快照（366 MB）迁出回收站 + 建可检索索引。
- ✅ 静态门禁（`validator-check`）全绿：无占位符残留、安全三条件（退出/幂等/回滚）齐备。
- 📌 **期望对齐的诚实结论**：「不丢资产 + 可证伪 + 把该收的收回来」三条已解决；
  「空间治理干净 + 文件整理归位」**未完成** —— 本次只覆盖了信息量最小的一层
  （21 个空壳 vs 1.9 GB / 283 个文件）。
- 📌 **顺带查出一个更隐蔽的隐患**：重跑素材库生成器会让 **2512/2567** 张卡 ID 漂移，
  而状态层按 ID 做键 ⇒ 生命周期数据会挂到别的卡上。**「重跑生成器」这个看起来正常的动作，实际是破坏性操作。**
- 📌 一个可复用的边界声明：回收站的「放回原处」依赖系统元数据，
  脚本无法还原原始路径 ⇒ **只能按文件名反查归属**，这是本方法的固有边界。

## 五、踩坑 → 规则反哺（复利点）

| 踩坑 | 反哺规则 |
|---|---|
| 审计范围容易只覆盖「已发生的动作」 | **审计对象比动作大一圈**：已执行的动作自查，即将执行的动作提前备证 |
| 「空目录」被当成「可能藏东西的目录」反复怀疑 | **把安全性编码进工具**：能用只作用于空目录的工具，就不必靠检查兜底 |
| 备份快照被误判为「无副本 = 危险」 | **无副本 ≠ 孤本**：快照/归档**按定义**就没有副本，应单列一档 |
| 把「已进真源库」当成「已安全」 | **备份层 ≠ 存档层**：真源库存在 ≠ 已提交版本历史；清理前须查未提交改动 |
| 迁移后的空壳被当成异常 | **迁移尾气的判据是「活体库同名目录非空」**，命中即正常残留，不必回滚 |
| 判定全靠人开箱，成本高且易漏 | **先查登记层，再开内容层**：台账 0 命中 ⇒ 非产出资产（省掉开箱）；只对例外做内容核查 |
| 清理完不知道算不算达成了目标 | **先显式化「期望」，再逐条对账**；否则「清理了」会被误当成「治理好了」。本例：清空目录是信息量最小的一层，却最容易被当成任务完成 |
| 把「动作做完」当成「目标达成」 | **动作 ≠ 期望**：写清 AC 前先写清「我们到底要什么」，两者混同会让验收空转 |
| **把「文件在哪」当成真问题** | **真问题常在「工序」不在「文件」**：本例文件有 3 份副本安然无恙，断的是「生成了 → 入库了」这一段。查资产别只查文件，要查**它该走的流程走完没有** |
| **自以为「唯一份」就下结论** | **「唯一」必须实测**：本例初版凭「文件名没搜到」就断言全机唯一，实测有 3 份 md5 相同的副本。**同名匹配的排除规则（如跳过备份目录）会造出假独本** —— 断言「唯一」前先确认自己的搜索没有盲区 |
| **以为「重跑生成器」无害** | **自动生成 ≠ 幂等**：重跑前先在沙箱比对 ID/键的稳定性。键不稳定 + 状态层按键存取 = 重跑即错配 |
