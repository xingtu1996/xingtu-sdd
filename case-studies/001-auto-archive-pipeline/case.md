# Case 001 · 自媒体文章自动归档流水线

> **一句话**：发完即归档——把「发了文章 → 链接/台账/镜像仓全手动维护」改成「抓取 → 规范化 → 台账 → 镜像入库 → 主页联动」六步流水线，人只做终审。
> **档位**：standard ｜ **状态**：✅ 已跑通（D1 半自动）｜ **原 spec**：`specs/20260907-自媒体文章自动归档流水线/`

## 一、背景问题（为什么做）

- 文章发了，链接靠人工丢、台账靠人工回填——发布日志的「链接为空 = 未闭环」是常态，**发一篇漏一篇**。
- GitHub 镜像仓与主页「最新文章」全靠手动维护，滞后且易断。
- 目标：公众号 / 小红书 / 掘金 / CSDN / 知乎已发布内容**自动抓取正文 + 链接 → 台账 → 归档联动**。

## 二、Spec 结构（怎么组织）

```
00_README.md           # 一句话 + 为什么做 + 流水线总览 + 红线（不可协商）
01_归档流水线SOP.md     # 六步详细操作 + 判定规则
02_抓取通道矩阵.md       # 各平台抓取方式对比（浏览器通道/API/网页抓取）
03_台账与联动规范.md     # 台账 schema + 双仓联动规范
04_待办清单.md          # 自动化待办（登录态/频控/定时）
```

## 三、关键设计（怎么实现）

- **六步流水线**：触发源 → ①抓取（链接+正文+配图）→ ②规范化（YAML 头+图片引用）→ ③台账登记 → ④镜像入库 → ⑤主页联动 → ⑥终审回填（72h/7d 数据）。
- **通道矩阵**：主渠道（浏览器登录态抓后台「发布记录」）；备选（官方页面抓取）；扩展平台用网页抓取即可。
- **规范化产出标准**：镜像 md 用 SEO/GEO 英文 slug，YAML 头含 `title/date/tags/original/views/category/author`，配图占位转 markdown 引用。
- **红线先行**（不可协商清单）：未群发全文不上公网（原创首发时序闸门）；隐私扫描全绿才推送；未来排期稿不进 main 分支；镜像不改写原文（去 AI 味门禁不作用于已发布内容）。

## 四、验收结果（怎么算完成）

- ✅ D1 已跑通：本地发布包 → 镜像仓入库 + 主页「最新文章」插行（半自动路径，当日验证）。
- ✅ 公众号后台抓取通道实测可用（提取已发短链 + 阅读数）。
- ⬜ 全自动待办：定时增量比对、频控、登录态保活。

## 五、踩坑 → 规则反哺（复利点）

| 踩坑 | 反哺规则 |
|---|---|
| 未发布就上公网 = 原创声明失效 | 时序闸门：**链接存在才算已发布**，否则不进公网镜像（解锁开关） |
| 人工回填必然漏 | 判定闭环：台账「链接」列为空 = 未闭环，流水线强制 |
| 镜像内容被顺手改写 | 去 AI 味门禁只针对新稿，**已发布原文不改写**（镜像即原文） |
