# 过程证据索引

> 用途：**交付物的由来**放这里。判据——它解释了"结论怎么来的、为什么不是另一个方案"。
> 注意：本目录若被 `05_validator.md` 引用，即为校验链的一等依赖，**不得随交付清理**。
> 权威：本索引是 `execution-log.md` 的派生物，两者冲突以日志为准。

## 索引

| # | 文件 | 类型 | 生成方式 | 关联 AC | 是否已进交付 |
|:--:|---|---|---|---|:--:|
| 1 | — | — | — | — | 否 |

**类型枚举**（超出请先问是否该新增）：`审查` / `验证` / `计划` / `对比` / `裁剪` / `注记` / `待办`

## 写法

- **命名带日期**：`{主题}_{YYYYMMDD}.md`
- **文件头写清楚**：生成时间 / 用途 / 密级。接手的人靠这三行判断要不要读。
- **只写结论与依据**，不要复述正文。正文在 `01~05`。
- **"是否已进交付"**：`是` 表示它的结论已经进了交付物（过程件本身仍留在 `_work`）；`否` 表示还没被采纳。

## 什么该放这里

| 类型 | 例子 |
|---|---|
| 审查 | 对抗审查报告、交叉核对、专家意见 |
| 验证 | 实测记录（命令 + 输出）、复现步骤 |
| 计划 | 执行 plan、任务拆解草案 |
| 对比 | 版本 diff、方案对比、口径对照 |
| 裁剪 | 从交付物里删掉了什么、为什么 |
| 注记 | 内部备忘、不主动对客户讲的备答 |
| 待办 | 给下一次会话续接用 |

## 不放进这里

- 对外交付的成品 → `deliverables/`
- 历史版本 → `_archive/`
- 用户原话/一手材料 → `_prompt/`

## 清理判据

文件超过 30 个时先问：哪些已经被 `00_README` 或 `05_validator` 引用？
- 被引用的 → 必须留
- 没被引用、且结论已经进了正文的 → 可移入 `_archive/`（它变成了历史，不再是过程）
