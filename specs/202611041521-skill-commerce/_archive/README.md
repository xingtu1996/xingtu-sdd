# 历史版本归档

> 用途：**曾经在 `deliverables/`、现在不在**的版本放这里。
> 判据——别人问"为什么改成这样""上一版长什么样"时，能从这里翻出来。
> 规则：**只移动不删除**；现行版永远只在 `deliverables/`；每归档一版必须补一行。

## 版本索引

| 版本 | 文件 | 主要变化 | 作废原因 | 归档时间 |
|:--:|---|---|---|---|
| **V1（现行）** | `../deliverables/—` | 首版 | — | — |

## 归档规则

1. **只移动、不删除**。文件名保持原样，靠版本号区分。
2. **新增一版时**，把上一版从 `deliverables/` 移入本目录，并在上表补一行。
3. **现行版永远只在 `deliverables/`**，本目录不放现行版。上表里「现行」那一行指向 `deliverables/` 下的文件。
4. **归档 = 移动 + 登记 + 回写**（不是只挪文件）：
   - 文件移入本目录
   - 本表补一行
   - `execution-log.md` 追加一条
   - `00_README` 索引里指向旧版本的行改指新版本

## 用命令做

```bash
bash ~/.claude/skills/specs-engine/scripts/sdd.sh archive <spec目录> <文件> \
  --version V8 --reason "缺基线引用与可见性"
```

## 为什么「作废原因」是必填

它是这张表唯一不能被 `ls` 替代的信息。文件名和日期都在磁盘上，**"为什么不用了"只在人脑子里**。
不写，下一个人只能猜，猜错就会把作废的口径又用回去。

（这一点与 ADR 的 `Status: Superseded` + `Consequences` 是同一个思路：Nygard, 2011。）

## 子目录同样适用

`deliverables/` 下任何子目录里出现历史版本，同样要移到这里。只盯根目录，版本会换个位置堆回来。
