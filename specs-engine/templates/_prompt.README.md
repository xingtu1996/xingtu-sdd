# 输入来源索引

> 用途：**复现不出的原始输入**放这里。判据——换个 AI / 换个人，缺这段就复现不出同一个结论。
> 定位：**这是「以始为终」的脊椎**。规格从哪来，全看这里。产出可以重做，输入不可复现。
> 权威：本索引是 `execution-log.md` 的派生物，两者冲突以日志为准。

## 为什么它是脊椎，不是附件

规格驱动（SDD）的前提是「规格定义好了，就能操作」。但规格不会凭空出现——它由一串原话逼出来。

只留产出、不留输入，会有三个后果：

| 后果 | 长什么样 |
|---|---|
| 说不清"为什么是这样而不是那样" | 下一个人只能猜，猜错就重做 |
| 纠偏被抹掉 | 最终决定往往是绕了弯路才到的，弯路里藏着真约束 |
| 规格无法演化 | 需求变了，不知道当初基于什么前提，只能推倒重来 |

**所以：原始提示与关键提示尽可能全录，包括被推翻的、说错后改口的。**

## 两个必录清单

| 类型 | 录什么 | 为什么 |
|---|---|---|
| **原始提示** | 任务怎么开的头、给了哪些参照物 | 决定方向 |
| **关键提示** | 中途改口的、纠正 AI 的、加码边界的 | **最高密度的 why**，往往比初版需求更能说明真实约束 |

**判据**：一句话如果能解释"某个产出为什么长这样"，就该录。

## 写法

- **逐字，不改写**。原始提示词/邮件/群聊照录，错字也保留；需要归纳的写进 `01_analysis`，不要写在这里。
- **一源一文件**。一封邮件一个文件，一场会议一个文件；不要把不同来源揉进一个。
- **标密级**。`内部` / `敏感` / `可对外`；敏感件不进会推的仓。
- **对应产出**填文件名或 AC 编号，说明这段输入支撑了哪个结论。

## 不放进这里

- 你自己写的分析、总结、判断 → 那是 `_work/` 或正文
- 已定稿的对外材料 → `deliverables/`
- 大体积原始数据（录音/视频）→ 原处留路径指针即可，不搬进来
