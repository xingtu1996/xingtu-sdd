# Specs 并行编排 — 多 Spec / 单 Spec 任务级并行（仅并行场景读）

> 何时触发：2+ 独立 Spec 并行、单 Spec 跨模块拆分、跨服务/跨仓侦查。单个串行任务不读本文件。

## 一、多 Spec 并行（契约优先）

```
Step 1: 构建依赖 DAG（检索 3 跳调用链/共享表/共享文件）
Step 2: 分类 → 串行组（有依赖）vs 并行组（完全独立）
Step 3: 跨单元握手协议先定死（provider 签名 + consumer 幂等 + 降级）→ 契约目录
Step 4: 独立组全并行推进（契约定了就能解耦）
```

| 依赖类型 | 策略 |
|---------|------|
| 接口依赖（A 调 B） | 先定契约 → 并行开发 |
| 数据依赖（共享表/字段） | 先改 schema → 并行 |
| 完全独立 | **并行** |
| 同文件改动 | **串行**（防 merge conflict） |

契约变更 → 更新契约目录 + 变更日志，让并行组读日志自适配，不靠人肉同步。

## 二、单 Spec 内任务级并行决策

定位：多 Spec 并行的下钻——**单个 Spec 内部**任务是否可并行、选哪种形态。
产出：01_analysis 并行性分析表 + 04_tasks 用 `∥` 标注可并行 Phase。

```
① 复杂度: 单文件/<20行 → 串行 ｜ 2-5 文件/1-2 模块 → 单执行单元 ｜ 跨 3+ 模块/大改 → 并行评估
② 拆分:   按模块/文件/Phase 拆 N 单元
③ 依赖:   强制 → 串行或 pipeline（拓扑序）｜ 选择/直接 → 契约化后并行 ｜ 无依赖 → 全并行
④ 形态:   见下速查表（以所用 agent 生态能力为准，不引外部编排工具）
```

## 三、形态速查表

| 场景 | 形态 | 容器/单元 |
|------|------|:---:|
| 1-2 模块，独立子任务 | 容器内 parallel 子执行体 × N | 容器=工作流，单元=子执行体 |
| 有依赖子任务（拓扑序） | 容器内 pipeline 子执行体 | 容器=工作流 |
| 单 Spec 跨 3+ 模块 | 并行按模块 | 容器=工作流 |
| 2+ 独立 Spec | 多组并行工作流 | 容器=多条工作流 |
| 跨模块/跨服务排查 | 多执行体蜂群（不经容器） | 直接并行 |
| 文件冲突不可避免 | 串行 | — |

## 四、质量门禁

- 并行声明须过**文件冲突验证**（各单元修改清单交集 = ∅）才可执行
- 并发上限 ≤ 编排工具默认（建议 3-5，勿盲目开满）
- **无并行价值时结论写「串行」，不强制并行**（并行是手段不是目的）
- 跨 Spec 并行升级走 §一 契约优先
