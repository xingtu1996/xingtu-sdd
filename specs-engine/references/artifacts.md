# 证据目录 — `_prompt/` `_work/` `_archive/`（按需读）

> 适用：长周期、多版本、有对外交付或需要"换个 AI 也能接着干"的 spec。
> **不是每个 spec 都需要。** 实测 58 个 spec 里只有 1 个完整用了三件套。
> 用法：拿不准某份文件放哪时读本文件；其余时候不用读。

---

## 1. 三个目录是什么

| 目录 | 一句话判据 | 回答的问题 | 典型内容 |
|---|---|---|---|
| `_prompt/` | **复现不出这个结论的原始输入** | 用户到底说了什么？ | 用户逐字提示词、一手邮件/群聊原文、审阅 prompt、原始会议转写 |
| `_work/` | **交付物的由来** | 这个结论怎么来的？ | 对抗审查报告、diff、验证记录、执行 plan、裁剪记录、内部注记、待办 |
| `_archive/` | **曾经在 deliverables、现在不在** | 为什么改成这样？上一版长什么样？ | 历史版本 + 版本索引表（含作废原因） |

三者合起来是一条证据链：**输入 → 过程 → 产出**。

**为什么用 `_` 前缀**：文件树按名排序时排在数字之后，主组件（`00_README` ~ `05_validator`）永远在最上面，过程件不抢视线。与「时间戳必须作前缀，靠 IDE 排序找 spec」是同一条道理。

## 2. 怎么判（按顺序问，命中即停）

```
这份东西是给谁看的？
  ├─ 客户 / 上级 / 外部           → deliverables/
  ├─ 未来的我或接手的 AI，
  │  要知道"我当初说了什么"        → _prompt/
  ├─ 未来的我或接手的 AI，
  │  要知道"结论怎么来的"          → _work/
  ├─ 曾经在 deliverables，被替换了 → _archive/
  └─ 都不是                        → 不进 spec
```

### 2.1 三个边界样本

| 文件 | 该放哪 | 为什么 |
|---|---|---|
| 客户发来的原始邮件 | `_prompt/` | 它是结论的起点；改了它，结论就得重推 |
| 我们写的同一封邮件的 V7 版（已被 V13 取代） | `_archive/` | 它是产出，只是过期了 |
| 对抗审查报告（指出 6 个 P0） | `_work/` | 它解释了为什么最终稿长这样，但不对外 |
| 中文对照稿（给内部人读英文件用） | `_work/` | 是辅助件，不是交付件；暂归此 |
| 定稿的英文邮件 | `deliverables/` | 对外交付 |

## 3. 三条硬规则

| # | 规则 | 理由 |
|:--:|---|---|
| **R-1** | `deliverables/` **只放当前有效版本**，历史版本一律进 `_archive/` | 新旧版并存会让人改错源（实测发生过：PPT 两个版本，磁盘上的 pptx 是旧版） |
| **R-2** | `deliverables/` 的**子目录同样适用 R-1** | 规则只管根目录时，版本会换个位置堆回来（实测：`deliverables/宋总沟通版本/` 堆了 16 项，含 `.bak` 与 v2/v3） |
| **R-3** | `_work/` 若被 `05_validator` 引用，即为校验链一等依赖，**不得随交付清理** | 校验器直接读 `_work` 里的文件时，删了就断链 |

## 4. 何时建、何时不建

| 目录 | 建 | 不建 |
|---|---|---|
| `_prompt/` | 有一手原始材料（客户邮件/会议转写/用户长指令），且结论需要可复现 | 需求来自工单或你自己的分析，没有外部原文 |
| `_work/` | 做过独立审查/实测/方案对比，或交付物被大幅裁剪过 | 一次成型、无过程可留 |
| `_archive/` | `deliverables/` 出现第 2 个版本 | 只交付一版，没有历史 |

**轻量 spec 一律不建。** 三个目录是为"跨多天、多次进出、多版迭代"准备的，短平快的任务建了只是负担。

```bash
# 一次性建三个（含 README 骨架）
bash ~/.claude/skills/specs-engine/scripts/scaffold.sh new <父目录> <名> --with-artifacts
```

## 5. 权威排序（冲突时听谁的）

```
execution-log.md   ← append-only 事实源，最高
    >
各目录 README 索引   ← 派生物，可能腐烂
    >
00_README / 正文     ← 叙述层
```

**索引与日志冲突时，以日志为准。** 这不是偏好：实测中 `_archive/README.md` 自称「V7 现行」，日志与磁盘都是 V13 —— 索引是人工维护的，日志是动作时写的，后者更接近事实。

推论：**能从日志重建的，不用在索引里重复记**。索引只记日志里没有的（如"这一版为什么作废"）。

## 6. 归档不是移动文件

开源对标 **OpenSpec** 的做法：`/opsx:archive` 不只把提案移到 `changes/archive/`，还**把 delta spec 合并回主 spec**。

照此，我们的归档动作 = **移动 + 登记 + 回写**：

1. 文件移入 `_archive/`
2. `_archive/README.md` 补一行（版本 / 主要变化 / 作废原因 / 时间）
3. `execution-log.md` 追加一条
4. `00_README` 索引里指向旧版本的行改指新版本

```bash
bash ~/.claude/skills/specs-engine/scripts/sdd.sh archive <spec目录> <文件> \
  --version V8 --reason "缺基线引用与可见性"
```

## 7. 三个 README 必须写什么

| 文件 | 必须有的列 | 为什么 |
|---|---|---|
| `_prompt/README.md` | 文件 / 来源 / 时间 / 对应产出 / 密级 | 让人知道"这段输入支持了哪个结论" |
| `_work/README.md` | 文件 / 类型 / 生成方式 / 关联 AC / 是否已进交付 | 让人知道"这堆东西哪些还有用" |
| `_archive/README.md` | 版本 / 文件 / 主要变化 / 作废原因 / 归档时间，**且含一行「现行」** | 有「现行」行才能机器检查"表里最新一行 = 现在该用的版本" |

`_work` 的类型限定为：`审查` / `验证` / `计划` / `对比` / `裁剪` / `注记` / `待办`。要加新类型先问，别默默开新类。

## 8. 防腐（索引会烂，必须机器查）

`Context Rot`（Treude & Baltes, arXiv:2606.09090, 2026）实测 356 个仓库中 23.0% 存在失效引用；我们自己的样本是 `_archive/README` 停在 V7 而版本已到 V13、25 个文件漏登 11 个。**规则写在纸上不检查，就会这样。**

`validator-check.sh` 的 **V-6** 检查三件事：

| 检查 | 级别 | 说明 |
|---|:--:|---|
| 归档目录有无 README | WARN | 没有索引就等于没有归档 |
| 归档文件是否都已登记 | WARN | 列出未登记文件（最多 5 个） |
| 「现行」行是否指向 `deliverables/` 下真实存在的文件 | ERROR | 指向归档或不存在 = 接手人会拿到作废版本 |

**没有 `_archive/` 目录的 spec 完全静默**，不告警。

## 9. 文献依据（为什么这么做，不是我们发明的）

| 做法 | 依据 |
|---|---|
| 把 prompt / 原始输入当一等实体留档 | **PROV-AGENT**：扩展 W3C PROV，显式捕获 agent 的 prompts、responses、decisions（arXiv:2508.02866，IEEE e-Science 2025） |
| 记录"为什么不是另一个方案" | **gIBIS**：Issue / Position / Argument 三元结构（Conklin & Begeman, ACM TOIS 1988） |
| 版本永不删除、状态含 Superseded | **ADR**：五段式 + Status（Nygard, 2011） |
| 归档时回写主文档 | **OpenSpec**：`/opsx:archive` 合并 delta spec 到主 spec |
| 持久化策略"没有默认" | **GitHub Spec Kit**：Spec Persistence Models 明说三种策略都非必需 |
| 索引必须机器检查 | **Context Rot**（arXiv:2606.09090） |

诚实声明：以上文献支撑"**为什么要留**"，不支撑"**必须叫这三个名字**"。命名来自本项目的实践，不冒充学术结论。没有找到专门研究 SDD 目录归档结构的论文。

## 10. 一句话

**`_prompt` 存输入，`_work` 存过程，`_archive` 存历史；判据三问，权威看日志，索引靠机器查。**
